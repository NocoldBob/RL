## 前言：先修正第一篇里的两个问题

第一篇文章的目标，是用尽量少的算力让新人看到一个能动起来的强化学习项目。这个方向没有
问题，但重新检查代码后，我发现有两个概念必须认真修正。

第一，旧代码被称为 SAC，实际上实现的是一个单步 Actor-Critic。第二，环境里的启发式规则
会覆盖模型给出的动作，但训练时仍然用模型原动作计算损失。这样一来，环境真正执行的动作
和模型学习的动作不是同一个动作，最终表现也不能证明模型真的学会了。

教程最重要的不是展示一个漂亮结果，而是让实验结论可信。因此本篇不急着增加新算法，先把
环境、动作、训练和评估关系理顺。

## 一、当前实现为什么不是 SAC

SAC 的全称是 Soft Actor-Critic。现代 SAC 通常包含：

1. 一个随机策略 Actor；
2. 两个 Q 网络；
3. 目标 Q 网络；
4. 经验回放池；
5. 最大熵目标以及温度参数 `alpha`；
6. 从批量历史样本中进行离策略更新。

旧版贪吃蛇模型只有一个策略头和一个状态价值头，每执行一步就用 TD 误差更新一次，没有
经验回放、双 Q 网络和目标网络，`alpha` 参数也没有参与损失。因此准确名称应该是：

**带卷积编码器的单步 Actor-Critic。**

这并不代表它没有教学价值。Actor-Critic 比 SAC 更简单，反而适合作为新人的第一个策略
梯度实验。真正的问题不是算法简单，而是名字和实现必须一致。

| 对比项 | 当前贪吃蛇 | 标准 SAC |
|---|---|---|
| 动作空间 | 左转、右转、直行三个离散动作 | 通常用于连续动作 |
| Critic | 一个状态价值 `V(s)` | 两个动作价值 `Q(s,a)` |
| 经验回放 | 无 | 有 |
| 目标网络 | 无 | 有 |
| 熵正则 | 少量策略熵奖励 | SAC 核心目标 |
| 更新方式 | 每一步在线更新 | 从回放池批量更新 |

所以后续课程会先把 Actor-Critic 和 DQN 讲清楚，真正的 SAC 将放在连续动作环境中单独讲。

## 二、最隐蔽的问题：环境不能偷偷替模型做决定

旧代码在 `environment.step(action)` 中枚举三个动作，再根据安全路径和食物距离选择
`best_action`。这相当于模型说“向左”，环境却可能执行“向右”。

训练代码随后仍然执行：

```python
agent.update(state, action, reward, next_state, done)
```

这里的 `action` 是模型选择的动作，而奖励和下一状态来自 `best_action`。策略梯度建立在
“动作导致结果”的因果关系上，两者一旦不对应，梯度就失去了正确含义。

新版本规定：

> `env.step(action)` 必须原样执行 `action`，任何教师策略都不能在环境内部改动作。

环境会在 `info` 中返回实际动作，方便测试：

```python
observation, reward, terminated, truncated, info = env.step(action)
assert info["executed_action"] == action
```

自动测试还会检查蛇头的实际移动方向，防止以后重构时再次引入动作覆盖。

## 三、想保留“老师带路”，就明确做行为克隆

启发式规则本身并不是坏东西。对于低算力教学，它可以减少模型早期一直撞墙的挫败感。
问题只在于不能把它伪装成模型动作。

新环境提供一个显式方法：

```python
teacher_action = env.teacher_action()
```

训练程序在教师阶段采用下面的流程：

```python
state = as_tensor(observation, device)
action = env.teacher_action()
next_observation, reward, terminated, truncated, info = env.step(action)
imitation_loss = agent.imitation_update(state, action)
```

这里有三个关键点：

1. 教师动作由训练程序主动请求；
2. 环境执行的就是这个教师动作；
3. 示范进入小型回放集，Actor 用随机批量交叉熵模仿教师，这是行为克隆，不声称是强化
   学习更新；Critic 则学习教师轨迹的 TD 价值。

教师阶段结束后，代码切换到纯 Actor-Critic：

```python
action = agent.predict(state)
next_observation, reward, terminated, truncated, info = env.step(action)
agent.update(state, action, reward, next_state, terminated or truncated)
```

此时教师不再参与，动作、状态转移和梯度重新保持一致。

如果想观察完全从零探索的效果，可以关闭教师阶段：

```powershell
python .\贪吃蛇\main.py --teacher-episodes 0
```

## 四、Actor-Critic 更新做了哪些修正

### 状态必须包含蛇头方向

三个动作不是绝对的上下左右，而是相对于蛇头朝向的左转、右转和直行。旧观测只有蛇身、
食物和边界；蛇长度为 1 时，同一位置可能朝向四个方向，模型看到的画面却完全相同。这会
把问题变成部分可观测任务，模型无法确定左转后会到哪里。

新观测使用七个通道：蛇身、食物、边界，加上上、下、左、右四个方向 one-hot 通道。
这样动作含义才能由当前状态唯一确定。

### 网络与损失

模型仍然保持很小，方便在 CPU 上训练：

```python
self.feature_extractor = nn.Sequential(
    nn.Conv2d(input_channels, 16, kernel_size=3, padding=1),
    nn.ReLU(),
    nn.Flatten(),
)
self.actor = nn.Linear(feature_dim, output_dim)
self.critic = nn.Linear(feature_dim, 1)
```

Actor 直接输出 logits，并由 `Categorical` 构造离散动作分布。Critic 输出状态价值
`V(s)`。

TD 目标为：

```text
target = reward + gamma * V(next_state)
advantage = target - V(state)
```

终止状态不再累加下一状态价值。计算 TD 目标时使用 `torch.no_grad()`，避免梯度错误地
穿过下一状态网络：

```python
with torch.no_grad():
    _, next_value = self(next_state)
    target = reward
    if not done:
        target = target + gamma * next_value
```

总损失由三部分组成：

```text
loss = actor_loss + critic_loss - entropy_coef * entropy
```

少量熵奖励可以避免策略过早变成只选一个动作，但它只是普通 Actor-Critic 的探索辅助，
不能因此把算法叫作 SAC。

## 五、迁移到 Gymnasium

旧版代码使用 `gym`，并采用四返回值接口：

```python
observation, reward, done, info = env.step(action)
```

新版本迁移到维护中的 Gymnasium：

```python
observation, reward, terminated, truncated, info = env.step(action)
done = terminated or truncated
```

`terminated` 表示任务自然终止，例如撞墙或达到目标长度；`truncated` 表示达到最大步数
等外部限制。区分二者可以避免价值目标计算错误。

`reset` 也会同时返回 `observation` 和 `info`：

```python
observation, info = env.reset(seed=42)
```

环境现在通过 Gymnasium 官方检查器验证，观测值类型与声明的 `float32` 空间一致。

## 六、训练结果必须可复现、可独立评估

强化学习的波动很大，只展示一次成功动画很容易误导。新版本加入了以下约束：

- Python、NumPy、PyTorch 和环境都设置随机种子；
- 训练环境与评估环境完全分开；
- 评估使用确定性动作；
- 评估阶段不允许教师辅助；
- 奖励、得分和成功率分别记录；
- 检查点保存模型、优化器、轮次和环境参数。

独立评估的核心结构如下：

```python
eval_env = SnakeEnv(...)
observation, _ = eval_env.reset(seed=evaluation_seed)
action = agent.predict(state, deterministic=True)
observation, reward, terminated, truncated, info = eval_env.step(action)
```

这意味着 `best.pt` 是按照无教师评估奖励选择的，不是按照训练阶段的启发式成绩选择的。

## 七、安装与第一次运行

### 1. 获取代码

```powershell
git clone https://github.com/NocoldBob/RL.git
cd RL
```

### 2. 创建虚拟环境

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
```

### 3. 先跑流程检查

```powershell
python .\贪吃蛇\main.py --episodes 20 --teacher-episodes 5 --grid-size 6 `
  --end-score 4 --max-steps 100 --eval-interval 10 --eval-episodes 3
```

这个命令的目标不是训练出最强模型，而是检查环境、模型、评估、日志和检查点能否完整运行。

### 4. 运行默认实验

```powershell
python .\贪吃蛇\main.py
```

默认前 100 个 Episode 做行为克隆，后续进行 Actor-Critic 更新。训练产物保存在
`runs/snake`。

发布前在 Windows CPU、`seed=42`、`6x6` 网格上运行 500 Episode，最后一轮 20 次
无教师独立评估得到：平均奖励 `15.46`、平均吃到 `0.80` 个食物、通关率 `10%`。这组数字
只用于证明流程能够真实学习，不应当作性能结论；正式比较仍需要多个随机种子。

## 八、用 TensorBoard 比较两个实验

建议至少运行两组：

### 实验 A：完全从零探索

```powershell
python .\贪吃蛇\main.py --teacher-episodes 0 --output-dir runs\no-teacher
```

### 实验 B：先模仿教师

```powershell
python .\贪吃蛇\main.py --teacher-episodes 100 --output-dir runs\with-teacher
```

启动 TensorBoard：

```powershell
tensorboard --logdir .\runs
```

重点观察：

1. `train/reward` 是否整体上升；
2. `eval/reward` 是否同步上升；
3. `eval/score` 是否优于随机策略；
4. 教师阶段结束后，性能是否明显下降；
5. 多个随机种子下趋势是否一致。

> 此处插入 TensorBoard 中两组实验的奖励曲线截图。

教师训练奖励较高并不代表模型能力强。真正有意义的是教师退出后，独立评估曲线是否仍然
提高。

## 十、这次修正带来的教学价值

这次更新没有追求更复杂的网络，而是解决了几个更基础的问题：

- 算法名称和实现一致；
- 模型选择什么，环境就执行什么；
- 教师策略被明确标记为行为克隆；
- 训练成绩和独立评估成绩分开；
- 实验具备依赖、种子、测试和检查点。

强化学习最容易出现“程序看起来在跑，但结论并不成立”的情况。对新手来说，学会检查动作
与状态转移是否匹配，比一开始就堆复杂算法更重要。
